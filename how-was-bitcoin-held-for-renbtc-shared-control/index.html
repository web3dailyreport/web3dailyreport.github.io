How Was Bitcoin Held for renBTC? Shared Control

How was Bitcoin held for renBTC? RenVM kept BTC at gateway addresses controlled by Darknodes’ shared signing key, then authorized renBTC minting on Ethereum.

Blockfront Editorial

Nov 25, 2026 · 21:55 UTC2 min read

RenVM held Bitcoin backing renBTC at gateway addresses controlled by Darknodes’ shared signing key. The nodes used secure multi-party computation to authorize Bitcoin transactions together, so no single Darknode held the complete private key.

A transfer began when a holder sent BTC to a gateway address generated for that RenVM transfer. The BTC stayed at that shared address; it was not divided into separate balances for individual Darknodes.

After verifying the deposit, RenVM authorized a gateway contract to mint renBTC on Ethereum. For holders comparing options, sBTC and tBTC custody differences for RenBridge users help explain how the underlying BTC’s control affects the claim they hold. RenBridge was the interface for these cross-chain transfers.

How did distributed control work?

Darknodes collectively controlled the signing key through secure multi-party computation. Each node held a portion of key material and contributed to signing, while the complete key was never held by one node.

That arrangement let the network authorize Bitcoin transactions with threshold signing. The gateway address therefore had one Bitcoin balance, controlled by a key used collectively by the network.

On the destination chain, the gateway contract minted renBTC after RenVM verified the deposit. The new token represented a claim tied to BTC held at the Bitcoin gateway address; it was not Bitcoin moved onto Ethereum.

What did this mean for a holder?

Say you sent 0.1 BTC to a gateway address for a RenVM transfer. The 0.1 BTC remained at that address under the distributed signing arrangement, and after the deposit was verified, the gateway contract minted renBTC on Ethereum.

You could then use renBTC as an Ethereum token in DeFi. The distinction mattered: you held a token claim on Ethereum, while the BTC backing it remained at the gateway address and Bitcoin transactions required collective authorization.

This describes the historical system. RenBridge’s original service was discontinued, so these mechanics explain how its BTC backing worked rather than how to start a new transfer today.
