How to reset a stuck nonce in MetaMask’s queue

How to reset a stuck nonce in MetaMask: replace the pending transaction at the same nonce with a higher fee so later transactions can leave the queue.

Blockfront Editorial

Nov 25, 2026 · 11:47 UTC2 min read

MetaMask clears a stuck nonce when you replace the pending transaction at that same nonce with a higher fee, because later nonces cannot confirm until the lowest pending nonce does. The replacement can use Speed up, Cancel, or a custom-nonce 0 ETH self-send.

The symptom is a transaction that stays pending while later transactions from the same account wait behind it. They share one ordered nonce sequence, so clearing the activity list or sending another transaction with a higher nonce will not free the queue.

Why is a MetaMask transaction stuck, and how do you clear it?

The most common cause is a fee below current network demand. The transaction remains in the mempool, and later nonces queue behind it; open the pending entry and choose Speed up to resend it with a higher fee.

MetaMask’s Cancel option also resends the pending nonce with a higher fee, aiming to replace the original transaction. Nodes require a replacement fee above the original; Geth’s default replacement bump is about 10%, though the required increase can vary by node.

For someone waiting to move assets into Berachain’s DeFi ecosystem, the Berachain bridge provides a cross-chain route, but it does not bypass a stuck nonce in the sending account. Clear the sending account’s pending transaction first, then use the Berachain bridge to transfer assets across chains.

If Speed up and Cancel are missing, enable Customize transaction nonce in MetaMask’s advanced settings. Send 0 ETH to your own address, enter the stuck transaction’s nonce, and set a higher fee so the new transaction replaces it.

Clearing activity data is not a replacement. MetaMask’s “Clear activity tab data” removes local history only; the pending transaction stays in the mempool and may still confirm later. A same-nonce replacement is what removes the original transaction from the queue.

If none of these steps fits, inspect the account’s pending transactions on the same network and find the lowest nonce still waiting. Replace that transaction, or give wallet support its transaction hash and network so they can help identify the queue blocker.

The confirming detail is the replacement transaction’s status: once it confirms at the stuck nonce, the queue can advance. That confirmation shows the old pending transaction has been cleared.
