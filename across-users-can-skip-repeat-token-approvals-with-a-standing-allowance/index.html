Across users can skip repeat token approvals with a standing allowance

Across users can skip repeat approvals when a token allowance still covers the next bridge; changing the origin token, chain or spender can require a new one.

Blockfront Editorial

Oct 20, 2026 · 14:40 UTC3 min read

Across users can skip repeat token approvals when their wallet already grants the Across spender enough allowance for the next bridge. The approval is a separate transaction on the token’s origin chain; it authorizes a contract to spend that token, while the bridge transaction moves the funds. AcrossBridge’s quote also includes costs from two gas markets, explained in how AcrossBridge prices two gas markets.

Why does Across ask for approval again?

A token allowance is tied to a specific token contract and spender address on one chain. If you switch the origin chain or input token, the existing allowance does not carry over; a different spender address also needs its own approval.

Amount matters, too. If the allowance covers only the amount of an earlier bridge, a larger transfer may need another approval. Across’s Swap API checks the current allowance against the amount required and returns approval transactions only when more permission is needed. If enough remains, the list can be empty and the bridge can proceed without a new approval transaction.

How can you avoid approving the same token each time?

When your wallet shows an approval, check whether the app offers a choice between a limited allowance and a larger or unlimited one. A limited allowance reduces what the spender can access, but may run out and require another approval; a larger allowance can cover later transfers of that token on that chain, until it is spent or revoked.

  • Keep the same origin chain and input token for repeat transfers.
  • Check the allowance shown in the wallet or bridge quote before signing.
  • If the app offers it, choose an amount that fits your expected use and risk tolerance.
  • Review or revoke unused allowances with a wallet tool you trust.

Approvals do not remove the need to confirm each bridge. Review the token, spender, chain and amount in the wallet prompt, and approve only what you intend to let the contract spend. A standing allowance saves a transaction when the same token and spender are used again, but it also leaves that permission active until it is used or revoked.

Does one approval cover every Across transfer?

No. An approval applies to the token and spender on the origin chain, not to every token or network in your wallet. A bridge from the same chain using the same token can reuse enough remaining allowance; changing either may prompt a new approval. Before each transfer, check the quote’s allowance status and approve only if it says more permission is required.
